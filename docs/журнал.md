# Журнал проекту

Тут фіксуються емпіричні пороги, рішення й спостереження — що працює, а що ні. Ведеться з першого дня, щоб згодом на реальних даних вибудувати логіку керування.

## Агрономічні пороги

Огірки люблять тепло й високу вологість — приблизно 24–28°C і 75–90% вологості повітря. Бояться протягів. Пріоритет для них — полив і тепло. Сигналити треба, коли стає холодно або сухо.

Помідори навпаки — для них критично низька вологість, орієнтовно 60–70%. Якщо вологість зависока, з'являється ризик фітофтори й гнилі. Пріоритет — вентиляція й провітрювання. Сигналити треба, коли вологість піднімається вище норми.

Це стартові орієнтири з опису проекту. Реальні пороги уточнюватимуться за сезон на фактичних вимірах.

## Рішення по залізу

868 МГц — легально правильна LoRa-частота для України та Європи. Це не обговорюється.

Ємнісні датчики вологості ґрунту версії 1.2 обрано замість резистивних: резистивні кородують і ненадійні. Абсолютна точність тут не потрібна — достатньо для тригера поливу. Калібрування гравіметричне, кухонними вагами й духовкою.

SHT31 обрано замість DHT11/DHT22 через комерційну надійність для реального розгортання.

Heltec V3 обрано замість V4 — платформа зріліша, а конектор для сонячної панелі у Фазі 1 не потрібен.

Raspberry Pi 5 обрано замість вживаного міні-ПК — офіційний комплект прибрав різницю в ціні. microSD SanDisk/Kingston з рознесенням зносу через цілодобовий запис у базу.

## Спостереження

**2026-07-22 — перше підключення Heltec WiFi LoRa 32 V3 (863-928 МГц)**

Заводська тестова прошивка на платі показала "Lora: Error" при першому включенні. Це не поломка — факт-тест робить ping-pong між двома платами з однаковою прошивкою; з однією платою йому нема з ким звʼязатись, тому валить помилку. Wi-Fi скан (знайшов 3 мережі) підтвердив що плата робоча.

Налаштування середовища розробки:
- PlatformIO встановлено локально через `pipx install platformio`.
- Створено проєкт `firmware/greenhouse-node` (`pio project init --board heltec_wifi_lora_32_V3`).
- Додано `firmware/Dockerfile` для збірки прошивок у контейнері — заливка на плату (`upload`) все одно йде з хоста, бо Docker Desktop на macOS не прокидає USB-порти в контейнер.
- Деталі команд і структури — у `firmware/README.md`.

Наступний крок — базовий send/receive скетч під протокол з `greenhouse_architecture.md`, з правильною частотою (868 МГц, EU868) замість заводського тесту.

**2026-07-22 — перший успішний білд і заливка (LoRa init OK)**

Довелось довести Docker/локальне середовище до ладу:
- Локальний pipx поставив PlatformIO під Python 3.14 — для нього нема готових wheel-ів `cryptography` (залежність `esptoolpy`), pip падав на збірці з джерела. Перевстановлено під Python 3.11 (`pyenv`) — вирішило.
- Той самий venv після перевстановлення лишився без модуля `pip` всередині (pipx-квірк) — підкладено через `python -m ensurepip --upgrade`. Обидва кроки тепер автоматичні в `make setup-host` (`firmware/Makefile`).
- Для власне компіляції прошивки (`project init`, `run`) ці проблеми не заважали — вона йде через Docker (`docker-compose.yml`, образ `agro-firmware` на Python 3.11-slim), де wheel-и є одразу. Локальний `pio` потрібен лише для `upload`/`monitor`, бо Docker Desktop на macOS не прокидає USB в контейнер.

Написано мінімальний бринг-ап скетч (`firmware/greenhouse-node/src/main.cpp`): ініціалізація SX1262 на 868 МГц + статус на OLED. Зібрано (`make build`) і залито на плату (`make upload`) без помилок — RAM 6.1%, Flash 9.7%.

Результат на платі: **`LoRa: OK`, 868 MHz** — радіомодуль реально ініціалізується, попередня "Lora: Error" від заводського тесту дійсно була лише через відсутність другої плати для ping-pong, не апаратна проблема.

OLED показував текст перевернутим — виправлено одним рядком `display.flipScreenVertically()` після `display.init()`.

Живлення: плата працює і живиться просто через USB-C кабель (5В, власний регулятор до 3.3В) — нормально для розробки. При підключенні LiPo через JST той самий USB-C одночасно заряджає акумулятор (в V3 є вбудована схема заряджання).
