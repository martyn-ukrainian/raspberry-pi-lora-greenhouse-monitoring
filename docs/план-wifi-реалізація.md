## Фаза 0 — шум від Wi-Fi (стенд, 30–45 хв)

Передумови: плата в ґрунті на столі, USB у ноуті; ноут і плата в одній мережі
(хотспот з «Максимальною сумісністю» або домашня — для шуму різниці нема).

| # | Крок | Команда / дія | Готово, коли |
|---|---|---|---|
| 0.1 | Приймач | `cd firmware/soil-calibration && uv run tools/ingest_sink.py` | надрукував `-DINGEST_URL=...`; лишити працювати |
| 0.2 | Контроль | `make deploy-soil-cal`, потім `make soil-log RUN=p0-nowifi`, 10 хв | `data/p0-nowifi-*.csv` ≥ 600 рядків |
| 0.3 | Найгірший випадок | `PLATFORMIO_BUILD_FLAGS='-DWIFI_SSID=\"…\" -DWIFI_PASS=\"…\" -DINGEST_URL=\"http://…\"' make deploy PROJECT=soil-calibration PIO_ENV=wifi_field_always`; `make soil-log RUN=p0-always`, 10 хв | у Serial видно `# POST 200`, sink рахує пачки; CSV ≥ 600 рядків |
| 0.4 | BURST | те саме з `PIO_ENV=wifi_field`; `RUN=p0-burst`, 10 хв | те саме; у CSV видно розриви `elapsed_s` на 1–3 с раз на 30 с — це норма |
| 0.5 | Підсумок | `uv run tools/soil_summary.py data/p0-*.csv` для кожного | σ по кожному каналу в трьох режимах |
| 0.6 | Рішення | таблиця з `план-wifi-телеметрії.md`, фаза 0 | рядок у `docs/журнал.md` і в `калібрування-ґрунту.md`: σ ×?, висновок, чи дозволена локальна сторінка |

Між 0.2→0.3→0.4 сенсори не чіпати, воду не лити: порівнюємо один і той самий
ґрунт. Якщо між прогонами ґрунт сохне — це видно як тренд середнього, не σ;
для рішення важлива σ.

Якщо `always` дає > 5× і `burst` теж — зупинка, гілка закривається, плата
повертається до USB. Усе нижче робиться лише після «зелено» або «жовто».

## Фаза 1 — прошивка

### Структура файлів

`main.cpp` уже 780 рядків; мережу виносимо окремо, щоб стенд і телеметрія не
зрослись в одне:

```
firmware/soil-calibration/src/
  main.cpp          — стенд, як є; викликає telemetry через 5 хуків (нижче)
  telemetry.h       — інтерфейс: telemetrySetup/Loop/Collect/Flush/Command
  telemetry.cpp     — усе, що зараз під #ifdef AGRO_WIFI, + портал, NVS, черга
  portal_html.h     — HTML порталу і локальної сторінки raw-літералами
```

Хуки в `main.cpp` (усі під `#ifdef AGRO_WIFI`, без прапорця — порожні inline):

| Хук | Звідки викликається | Що робить |
|---|---|---|
| `telemetrySetup()` | `setup()`, після прогріву | NVS → режим (портал / робота) |
| `telemetryLoop()` | `loop()`, кожен прохід | DNS + веб-сервер порталу; у роботі — нічого або сервер, якщо радіо піднято |
| `telemetryCollect(elapsed, water, event)` | `sample()` | як зараз `collectSample` |
| `telemetryFlush()` | команда `f`, кінець прогону | як зараз `flushBatch` |
| `telemetryCommand(line)` → bool | `handleCommand()`, перед `switch` | ловить `wifi …`, повертає true, якщо з'їла команду |

### 1а — портал і NVS

| # | Крок | Деталі | Готово, коли |
|---|---|---|---|
| 1a.1 | Винести чернетку в `telemetry.cpp` | чистий перенос, поведінка та сама; `wifi_field` збирається, фаза 0 за потреби повторюється на тому самому коді | збірка обох env, diff у `main.cpp` — лише хуки |
| 1a.2 | Конфіг у NVS | `Preferences` namespace `agro-net`: `n` (кількість мереж, ≤4), `ssid0..3`, `pass0..3`, `url`, `token`, `batch`, `last` (індекс останньої вдалої мережі). Прапорці `-DWIFI_SSID/…` стають **необов'язковими** і лише засівають порожній NVS при першому старті — для фази 0 і для столу без порталу | `#error` зникають; збірка без прапорців проходить; `wifi show` друкує конфіг (пароль зірочками) |
| 1a.3 | Вхід у портал | три тригери: NVS порожній; PRG (GPIO0) затиснута при старті ≥1 с; команда `wifi setup` у Serial | кожен тригер перевірено на платі |
| 1a.4 | AP + captive DNS | `WiFi.softAP("agro-calib-XXXX", "agro-calib")`, `DNSServer` на порт 53 → `192.168.4.1`; OLED: ім'я мережі, пароль, IP; у Serial те саме | телефон підключається, портал відкривається сам (iOS «Увійти», Android сповіщення) |
| 1a.5 | Сторінка порталу | `WebServer` на 80: `GET /` форма (до 4 мереж SSID/пароль, URL, токен, розмір пачки), `GET /scan` список мереж у ефірі (щоб не набирати SSID руками), `POST /save` → NVS → спроба STA з таймаутом 15 с → відповідь з результатом (IP або «не підключилось, перевір пароль / 2,4 ГГц») → через 3 с reboot у робочий режим | повний цикл з телефона: форма → збережено → плата в хотспоті; після reboot `wifi show` показує введене |
| 1a.6 | Ручна vs бібліотека | рішення на користь ручної (`WebServer` + `DNSServer`): список мереж, власні поля, той самий сервер потім віддає локальну сторінку. WiFiManager цього не дає без боротьби | — |

Пароль AP захардкоджений і не секрет (радіус 10 м); без пароля відкрита
мережа дратує телефони попередженнями.

### 1б — робочий режим

| # | Крок | Деталі | Готово, коли |
|---|---|---|---|
| 1b.1 | Підключення до списку | спершу `WiFi.begin(last)` з таймаутом 8 с; якщо ні — `WiFiMulti.run()` по всіх (сканує); вдалу запам'ятати в `last`. Це тримає паузу BURST близько 1–3 с, а не 5–6 | на столі: прибрав домашню → зайшла в хотспот, і навпаки; час підключення друкується в Serial |
| 1b.2 | Черга у LittleFS | `board_build.filesystem = littlefs`; кожна пачка → `/q/<seq>.json` перед спробою відправки; відправка проходить по файлах у порядку імен, 2xx → `remove`; RAM-черга прибирається. Ліміт: 2 МБ або 600 файлів → стирати найстаріший з `# черга переповнена` у Serial | вимкнув хотспот на 10 хв → файли накопичились → увімкнув → усе доїхало (sink показує 0 дублів, seq без дір) |
| 1b.3 | Команди `wifi` | `wifi show`, `wifi setup` (перезапуск у портал), `wifi clear` (стерти NVS), `wifi send` (= `f`), `wifi queue` (скільки файлів у черзі) | кожна працює |
| 1b.4 | Відповідь сервера → долив | після 2xx прочитати тіло; якщо `{"pour_ml": N}` — `addWater(N)` на платі, щоб `water_ml` і `event` були однакові в USB і в хмарі. Це те, що робить кнопку на сторінці «справжньою»: запис іде через плату, а не повз неї | sink (з прапорцем `--pour 50` один раз) → у наступному рядку USB-CSV `water+50.0` |
| 1b.5 | Локальна сторінка | той самий `WebServer`: `GET /` живі значення + σ за хвилину (рахує плата по кільцевому буферу 60), `GET /api/live` JSON, `GET /log.csv` — конкатенація черги. Працює, коли радіо піднято: у порталі завжди, у роботі — лише в `always`-режимі | у `wifi_field_always` з телефона в хотспоті видно живі значення |
| 1b.6 | README | розділ «Wi-Fi» у `soil-calibration/README.md`: як зайти в портал, iPhone-пастки, команди, що означають повідомлення в Serial | — |

Оцінка фази 1 разом: 5–7 годин.

## Фаза 2 — хмара: Vercel + Neon

> **Стан 2026-08-23:** код написаний і прогнаний на локальному Postgres
> (дедуп, долив через відповідь, повтор до підтвердження, NULL-поля, CSV) —
> `cloud/soil-telemetry/`. Сторінка фази 3 там само, перевірена в браузері.
> Лишилось: завести Neon і проєкт у Vercel (README там), і крок 1b.4 у
> прошивці, щоб кнопка доливу доходила до плати.

### Розташування й стек

```
cloud/soil-telemetry/
  api/index.py        — FastAPI: усі маршрути; Vercel Python runtime
  public/index.html   — сторінка (фаза 3), статична
  schema.sql          — таблиці; застосовується руками в Neon SQL editor
  requirements.txt    — fastapi, psycopg[binary]
  vercel.json         — rewrite /api/* → api/index.py
  README.md           — деплой, змінні, як дістати URL/токен
```

Python, а не Node: той самий стек, що `server/`, і проєкт частково про
практику Python. Vercel тримає FastAPI у Python runtime без танців.

Змінні середовища Vercel: `DATABASE_URL` (pooled-рядок Neon, обов'язково
pooled — функції коротко живуть, а ліміт з'єднань у Neon малий),
`INGEST_TOKEN`.

### Схема

```sql
devices(id text pk, label text, first_seen timestamptz, last_seen timestamptz)
batches(device text, seq int, received_at timestamptz, n int,
        primary key (device, seq))             -- дедуплікація за контрактом
samples(id bigserial pk, device text, seq int, t real, water_ml real,
        event text, raw int[], mv int[], air_t real, air_h real,
        received_at timestamptz)
pours(id serial pk, device text, ml real, created_at timestamptz,
      delivered_at timestamptz)                -- кнопка «влив N мл»
labels(device text pk, labels text[])          -- імена каналів з останньої пачки
```

`samples.raw/mv` — масиви, а не 8 колонок: кількість каналів задає плата.
Індекс `(device, received_at)` — сторінка читає «останні N».

### Маршрути

| Метод | Шлях | Що | Готово, коли |
|---|---|---|---|
| POST | `/api/ingest` | Bearer-перевірка; `INSERT batches ON CONFLICT DO NOTHING` — якщо конфлікт, 200 без запису (дубль); інакше вставити samples однією командою; оновити devices/labels; у відповідь `{"ok":true,"pour_ml":N}` якщо є недоставлений pour — і позначити delivered | `ingest_sink.py` замінюється хмарою: плата шле, `SELECT count(*)` росте; повторний POST тієї самої пачки не подвоює рядки |
| GET | `/api/devices` | список плат з `last_seen` | — |
| GET | `/api/live?device=` | останні 120 замірів + σ за 60 с по каналах (рахує SQL `stddev_samp`) + labels | JSON для сторінки |
| GET | `/api/export.csv?device=&from=&to=` | CSV рівно з колонками USB: `elapsed_s,water_ml,event,<label>_raw,<label>_mv,air_t,air_h` + `# received_at` у коментарі | `diff` з USB-логом у фазі 4 |
| POST | `/api/pour` | `{device, ml}` → `pours`; плата забере при наступному POST | кнопка на сторінці → рядок у `pours` → через ≤30 с `water+N` в USB-CSV плати |

Оцінка: 3 години (разом із заведенням Neon і першим деплоєм).

## Фаза 3 — сторінка

Одна статична `public/index.html`, без збірки: vanilla JS + `uPlot` (легкий,
з CDN). Опитує `/api/live` раз на 10 с.

| Елемент | Деталі |
|---|---|
| Вибір плати | `select` з `/api/devices`; одна — обирається сама |
| Поточні значення | великий шрифт, по каналах `mv` (`raw` дрібно), `air_t/air_h` |
| σ за хвилину | поруч з кожним каналом; > 3 мВ — жовтим, > 10 — червоним (пороги з `калібрування-ґрунту.md`) |
| «давно не було даних» | якщо `last_seen` > 90 с — банер: плата мовчить |
| Графік | `mv` усіх каналів за прогін, вертикальні мітки на `event` |
| Кнопка «влив N мл» | поле + кнопка → `POST /api/pour`; після натискання показує «чекаю підтвердження плати», гасне, коли в даних з'явився `water+N` |
| Експорт | посилання на `/api/export.csv?device=…` |

Телефон — головний екран: одна колонка, великі кнопки, без hover-залежностей.

Оцінка: 2–3 години.
