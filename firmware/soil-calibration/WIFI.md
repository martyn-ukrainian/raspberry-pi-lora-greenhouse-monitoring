# Wi-Fi-режим: як це робиться сьогодні

Робоча інструкція, а не план. Тут **тільки те, що вже працює** — усе інше
позначено як «ще нема».

## Що є і чого нема

Станом на 2026-08-23, після першого наскрізного прогону:

| | Стан |
|---|---|
| Wi-Fi піднімається з `.env`, без ручних прапорців | ✅ перевірено на залізі |
| Передача пачок у мережу | ✅ `POST 200`, 842 рядки прийнято |
| Колонки прийнятого збігаються з USB-CSV | ✅ звірено файлами |
| Радіо вимкнене під час заміру (`wifi_field`) | ✅ працює |
| USB-CSV одночасно з Wi-Fi | ✅ не вимикається ніколи |
| Локальний приймач замість хмари | ✅ `tools/ingest_sink.py` |
| SHT31 підхоплюється на льоту | ✅ 26,16 °C / 47,97% |
| Черга при обриві (4 пачки в RAM) | ⚠️ у коді, **обривом не перевірена** |
| **Фаза 0: чи псує Wi-Fi вимір** | ⏳ **прогін іде**, `tools/phase0.py` |
| **Портал `192.168.4.1`** | ❌ **ще нема** — фаза 1а |
| Черга у флеші, LittleFS | ❌ ще нема |
| Хмара на Vercel | ❌ ще нема |

**Найважливіший рядок тут — фаза 0.** Те, що тракт працює, ще не означає, що
ним можна калібрувати: питання не «чи доходять дані», а «чи не зіпсувала
передача те, що ми міряємо». Відповідь — таблиця σ, яку рахує `phase0.py`.

**Наслідок, який треба прийняти:** поки нема порталу, **зміна мережі означає
перезаливку**, а перезаливка означає ноут. Тобто «працює без ноутбука» поки
справджується лише доти, доки хотспот не змінився.

## Фаза 0: чи псує Wi-Fi вимір

**Це найважливіший дослід усієї гілки.** Наш шум σ = 0,6 мВ, і саме він дає
роздільність 0,15 мл води. Передача Wi-Fi — імпульси 200–300 мА, які
просаджують шину живлення, а від неї живиться ADC. Якщо σ виросте втричі, ми
проміняли вимірювальний прилад на зручний.

### Що потрібно

- сенсори **в ґрунті**, нерухомо (відро підійде, навіть мокре);
- ім'я й пароль домашнього Wi-Fi (**2,4 ГГц**; ESP32 5 ГГц не бачить);
- **30–45 хвилин, коли стіл ніхто не чіпає**.

### Порядок

**1. Підняти приймач** (окреме вікно, хай працює весь дослід):

```
cd firmware/soil-calibration
uv run --with pyserial tools/ingest_sink.py --port 8008
```

Він надрукує готовий рядок для прошивки:

```
у прошивку: -DINGEST_URL=\"http://192.168.0.42:8008/api/ingest\"
```

**2. Три відрізки по 10 хвилин.** Між ними не чіпати ні відро, ні дроти.

```
cd firmware

# А. контроль — Wi-Fi у прошивці немає взагалі
make upload PROJECT=soil-calibration
make soil-log RUN=phase0-a-nowifi     # 10 хв, потім q

# Б. радіо піднято постійно
PLATFORMIO_BUILD_FLAGS='-DWIFI_SSID=\"мережа\" -DWIFI_PASS=\"пароль\" \
  -DINGEST_URL=\"http://192.168.0.42:8008/api/ingest\"' \
  make upload PROJECT=soil-calibration PIO_ENV=wifi_field_always
make soil-log RUN=phase0-b-always     # 10 хв

# В. радіо імпульсами (штатний режим)
PLATFORMIO_BUILD_FLAGS='...те саме...' \
  make upload PROJECT=soil-calibration PIO_ENV=wifi_field
make soil-log RUN=phase0-c-burst      # 10 хв
```

**3. Порахувати шум** по кожному USB-логу:

```
uv run --with pyserial tools/soil_summary.py data/phase0-a-nowifi-*.csv
```

Дивитись треба на **σ**, не на рівень: рівень за 30 хвилин міг поплисти сам
(ми вчора заміряли температурний дрейф ~1,5 мВ/год).

### Як читати результат

| σ у режимі Б проти А | Висновок |
|---|---|
| виросла < 2× | Wi-Fi нешкідливий, можна навіть ALWAYS |
| виросла 2–5× | ALWAYS не годиться, дивимось на В (BURST) |
| В теж зіпсований | Wi-Fi для калібрування не годиться, крапка |

Відрізок **В** і є відповіддю на головне питання: чи рятує рознесення в часі.

## Польовий прогін сьогодні

Поки нема порталу — мережа вшивається при заливці, **вдома, з ноутом**:

```
cd firmware
PLATFORMIO_BUILD_FLAGS='-DWIFI_SSID=\"agro\" -DWIFI_PASS=\"11111111\" \
  -DINGEST_URL=\"http://...\" -DINGEST_TOKEN=\"...\"' \
  make upload PROJECT=soil-calibration PIO_ENV=wifi_field
```

У теплиці лишається тільки увімкнути роздачу на телефоні. Плата знайде
мережу сама.

### Пароль хотспота: чому його не можна дістати автоматично

Питання виникає щоразу, тож коротко: **ні, і не може бути.** Пароль Wi-Fi
ніколи не передається в ефір — ним лише *підтверджують знання*, не
розкриваючи. Якби сусідній пристрій міг його зчитати з мережі, WPA2 не мав би
сенсу.

Перевірено окремо (2026-08-23) і два шляхи, які здавались обхідними:

- **Зв'язка ключів Mac.** `security find-generic-password -wa "<SSID>"` дістає
  паролі мереж, до яких Mac підключався. Але для хотспота власного iPhone там
  **порожньо**: Mac заходить туди через **Instant Hotspot**, тобто через
  iCloud і взагалі без пароля. Зберігати було нічого.
- **Сканування мережі.** Показує, що пристрій є (`_apple-mobdev2._tcp`, ARP,
  reverse-mDNS дає ім'я), але не пароль. ESP32 Instant Hotspot не вміє — йому
  потрібен справжній.

Отже: *Налаштування → Режим модема → Пароль Wi-Fi*, руками, один раз.

### Ім'я телефона: перевіряти в налаштуваннях, не через mDNS

Пастка, на яку я вже попався. Через mDNS ім'я приходить **санітизованим**:
пробіли й спецсимволи замінюються дефісами. Реальне `Martyn — iPhone` (з
пробілами і **довгим тире**) виглядало як безпечне `Martyn-iPhone`, і я сказав,
що перейменовувати не треба.

Довге тире — не ASCII, і воно ламає прапорець збірки. **Ім'я дивитись у
Налаштування → Основні → Про цей пристрій**, а не в мережі. Найпростіше —
перейменувати на щось коротке латиницею (`agro`) і не думати.

### Три налаштування iPhone, без яких не запрацює

| Що | Де | Чому |
|---|---|---|
| **«Максимальна сумісність»** | Режим модема | інакше роздача на 5 ГГц, а ESP32 має лише 2,4 — мережі просто не буде видно |
| **Перейменувати телефон** | Основні → Про цей пристрій | стандартне `Ім'я's iPhone` має апостроф і пробіл, які ламають прапорці збірки |
| **Тримати екран режиму модема відкритим** при першому підключенні | — | iPhone гасить роздачу, поки ніхто не під'єднався |

Перше — найчастіша причина «не працює» і найменш очевидна: виглядає точнісінько
як неправильний пароль.

### Команди під час прогону

Ті самі, що в USB-режимі, плюс одна:

| | |
|---|---|
| `50` | долив 50 мл |
| `f` | **віддати недобрану пачку негайно** |
| `q` | завершити логування |

`f` наприкінці прогону обов'язкове: інакше останні до 30 замірів висять у RAM
і зникають разом із живленням.

## Що піде не так і як розпізнати

| Симптом | Причина |
|---|---|
| `# Wi-Fi недоступний` при старті | 5 ГГц, помилка в імені/паролі, або роздача згасла |
| `# POST -1` | приймач не запущений або інший IP |
| `# POST 401` | токен не збігається |
| Таймаут на **першому** запиті прогону | холодний старт бази (Neon засинає) — пачка піде в чергу й доїде |
| `# черга переповнена` | зв'язку не було >2 хв; у даних буде розрив |

**USB-CSV пишеться завжди й ніколи не залежить від мережі.** Якщо хмара
збрехала або замовкла — опорні дані на місці, і саме з ними звіряються.
