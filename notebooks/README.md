# Ноутбуки

Розрахунки на живих даних етапів 3 і 4. Висновки й межі застосовності — у
`docs/дослідження/`, тут — код і цифри, з яких ті висновки взято.

| Ноутбук | Питання |
|---|---|
| `01_burst_shape` | Форма бурста: шум і зсув `soil_raw` між ref і low, позиція в бурсті |
| `02_trend_dynamics` | Як швидко насправді змінюється ґрунт, і чи можна довіряти ref як еталону тренду |
| `03_window_selection` | З якого відліку бурста починати усереднення і на якому зупинятись |
| `04_soil_warmup` | Скільки чекати після Vext ON: крива прогріву замість оцінки `SOIL_WARMUP_MS = 3000` |
| `05_summary` | Підсумок серії: енергетика вузла, від 2 діб до 588 |
| `06_data_quality` | v1 проти v2: чи заплатили якістю даних за коротке вікно |

`scripts/` — чернетки на чистому pandas, з яких виросли 01 і 04. Лишені як є.

## Дані

`data/` — знімки з бази на момент розрахунку, не оновлюються автоматично.

| Файл | Що це | Звідки |
|---|---|---|
| `measurement.csv` | Таблиця `measurement` цілком, з 26.07.2026 | `agro.db` на Pi |
| `nodeevent.csv` | Таблиця `nodeevent`: boot, watchdog та інші події вузлів | `agro.db` на Pi |
| `stage4_pair.csv` | Парний прогін v1/v2 з 01.09.2026 | Neon, `node_measurements` |
| `soil_warmup_curve.csv` | Крива прогріву, прошивка `v2_soilprobe`, 2 прогони по 10 с | serial-лог; та сама копія лежить у `docs/assets/` |

## Запуск

```bash
cd notebooks
uv sync
uv run jupyter lab
```

Шляхи в ноутбуках відносні до цієї теки (`data/...`), тож ядро має стартувати
звідси. JupyterLab і VS Code роблять це самі.
