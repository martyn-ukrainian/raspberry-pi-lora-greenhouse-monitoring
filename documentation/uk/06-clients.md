# Клієнти

Три способи подивитись на дані; для оператора головний — Telegram.

| Клієнт | Для чого | Стан |
|---|---|---|
| Telegram-бот | сповіщення приходять самі; `/get` — поточні значення | ✅ основний канал оператора |
| `client/` — Android-застосунок | історія, графіки, алерти | ✅ працює на планшеті |
| `web/` — веб-сторінка | один екран із поточними значеннями | ⚠️ прототип, заморожено |

## Telegram

Описано в [05-server.md](05-server.md#telegram-бот): сповіщення про вихід за
пороги приходять автоматично з dwell/cooldown; `/get` показує останні значення
по всіх теплицях; доступ — адмін або підтверджений користувач.

## Застосунок (`client/`)

Expo SDK 54, React Native 0.81, TypeScript. Навігація — React Navigation
(нижні таби + стек), дані — TanStack Query, графіки — Victory Native + Skia,
стилі — NativeWind/Tailwind. Назва `AgroMonitor`, пакет
`com.martynukrainian.agromonitor`.

### Екрани

| Таб / екран | Що показує | Звідки дані |
|---|---|---|
| **Home** — список | картка на теплицю: три значення з останнього 5-хв бакета, міні-графік температури, індикатор сигналу (RSSI/SNR) | `/greenhouses`, `/measurements/aggregate`, `/measurements/latest` (оновлення 30 с) |
| **Home → деталі** | вертикальний свайп між теплицями, горизонтальний — між датчиками; графік з лініями порогів; min/max/avg і % часу в нормі; період `1h / 6h / 24h / 3d / 7d` | `/measurements/aggregate` з `since` + `bucket_minutes` (1/5/15/60/180 хв) |
| **Alerts** | список збережених алертів; бейдж = непрочитані; при відкритті всі позначаються прочитаними | `/alerts` (60 с), `POST /alerts/ack-all` |
| **Settings** | мітки теплиць і їхні пороги — **тільки перегляд**, редагування нема | `/greenhouses` |

Пороги редагуються на сервері в `thresholds.yaml`; застосунок їх лише
відображає.

### Налаштування й збірка

Адреса сервера — `EXPO_PUBLIC_API_URL` (`client/.env.local`), зараз
`http://192.168.0.88:8008`. IP зашитий, а не `agro-pi.local`, бо Android до 12
не резолвить mDNS із `fetch`. API по HTTP, тому в `app.json` увімкнено
`usesCleartextTraffic`.

```bash
cd client && npm install
npx expo start                              # dev на телефоні через Expo Go
eas build -p android --profile preview      # APK (~18 хв), профіль зашиває URL з eas.json
```

Профілі EAS: `preview` (internal, APK) і `production` (autoIncrement).
Історія: перший APK 2026-07-26; v1 падав на планшеті через розсинхрон версій
Expo-пакетів — звідси правило в `client/AGENTS.md`: перед будь-яким кодом
звірятися з документацією Expo SDK 54.

## Веб (`web/`)

Vite + React 19. Один екран: мітка **першої** теплиці, час останнього бакета,
три картки з середніми за 4 години, оновлення кожні 30 с (`/greenhouses`,
`/measurements/aggregate`). Адреса — `VITE_API_URL` у `web/.env.local`.
`npm run dev` / `build`. Зроблено як швидкий спайк до застосунку; далі не
розвивається, README — шаблон Vite. Якщо знадобиться веб — переписувати з
нуля під ті самі ендпоінти, а не тягнути це.

## Що планується

- Редагування порогів із застосунку (зараз — тільки YAML на сервері).
- Екран подій заліза (`/events`) — дані вже є на сервері.
- Сповіщення «вузол мовчить» — спершу на сервері, потім у клієнтах.
